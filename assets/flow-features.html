new static_state(st, M) for _ = 1:NEWTON_MAXITER▶

The static state at Mach M whose isentropic stagnation state is st — a new GasState, the input untouched. Same physics as gas_Mach!(·,0,M,1) but pure and zero-allocation; the speed of sound is evaluated at the static T (the Mach number is defined with the local sound speed), so it is a bounded Newton solve.

$$ h(T) + \tfrac{1}{2}\bigl(M\,a(T)\bigr)^2 = h(\text{st}),\qquad a^2 = \gamma R T $$

The only stagnation helpers use the constant-γ relations 1 + ½(γ−1)M² and (…)^(γ/(γ−1)) — γ frozen at one temperature. For a thermally-perfect gas those ratios drift with temperature and Mach (the figure below quantifies it).

new stagnation_state(st, M)▶

Brings the static flow isentropically to rest using the enthalpy and entropy curves — exact for a thermally-perfect gas. A loss-free reference: it carries no efficiency (a lossy ram composes separately). Closed form: one enthalpy inversion.

$$ h_t = h(T) + \tfrac{1}{2}V^2,\quad V=M a;\qquad P_t = P\,e^{\,(s^0(T_t)-s^0(T))/R} $$

design Why stagnation carries no efficiency

The legacy gas_Mach! took a polytropic ηp. The new pair drops it: a stagnation state is an isentropic reference (textbook definition), and keeping it loss-free is exactly what makes static_state and stagnation_state exact inverses — static_state(stagnation_state(st, M), M) == st to tolerance, verified to M = 3. A lossy ram or diffuser is composed separately (a pressure-recovery factor, or an expand). Losses compose; the reference does not.

ADR-0005 · src/flow.jl (working tree)

naming static_state / stagnation_state, not static / stagnation

The verbs are named with the _state suffix rather than the bare static/stagnation for two reasons: a bare static is a common identifier that would shadow (or be shadowed by) caller bindings, and the suffix says what they return — a GasState, echoing the GasState / entropy / density state vocabulary. speed_of_sound and mach stay bare: they return scalars and neither collides.
